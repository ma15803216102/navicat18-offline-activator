# Navicat 18 离线激活工具 · 使用说明

> **适用系统**：Windows 10 / Windows 11（64 位）
> **适用软件**：Navicat Premium 18（18.0.x 实测）
> **所需工具**：`Navicat18Tool-Offline.exe`（需自行构建，见 README「构建」）
> **全程耗时**：约 3～5 分钟
> **前置条件**：无卡密、无账号、无服务器——工具**全程不需要联网**

---

## 一、开始之前

请先确认这四件事：

| # | 检查项 | 说明 |
|---|---|---|
| 1 | **工具已经构建好了** | 本仓库**不附带成品 exe**。请先按 README 的「构建」章节跑完 6 步，得到 `bin\Navicat18Tool-Offline.exe` |
| 2 | **Navicat 18 已安装** | 或点工具里的【自动安装 Navicat】让它帮你下装 |
| 3 | **记住你的密钥对** | 构建时 `tools/gen_keys.py` 生成的 `keys/mykey_priv.pem` 是你的**签发私钥**，别删。换密钥 = 旧激活码全部作废 |
| 4 | **暂时关闭杀毒软件实时防护** | 见下方说明 👇 |

> ⚠️ **关于杀毒软件**
> 这个工具会修改 Navicat 的 DLL / 进程内存，属于典型的「被误报」行为。
> **请在激活过程中临时关闭实时防护**（或把工具与 Navicat 安装目录加入排除列表），激活完再打开。
> 如果工具被直接删除或双击没反应，基本就是这个原因。

> 💡 **和旧版（带扫码门禁的那个）的区别**
> 早期离线版每次启动要扫码换一个 6 位动态密码；**本开源版已经把这套门禁去掉了**——
> 没有卡密、没有二维码、没有手机网页、不连任何服务器。打开就能用。

## 二、激活流程（6 步）

### 第 1 步 · 打开工具

双击 **`Navicat18Tool-Offline.exe`**。

- 如果它弹 UAC（用户账户控制），点【是】——写 Navicat 安装目录需要管理员权限；
- 工具会**自动请求提权并重启自己**，不用你手动右键。

> 💡 主界面自上而下是：**目录** → 三个按钮（自动安装 Navicat / 安装补丁 / ⚡ 开始激活）→ **激活方式**切换 → 日志区。

---

### 第 2 步 · 确认 Navicat 安装目录

「目录」框一般会自动填好，例如：

```
C:\Program Files\Navicat\Navicat Premium 18\
```

- **路径正确** → 直接下一步
- **路径不对 / 是空的** → 点【选择目录】，手动选到**文件夹**（里面能看到 `navicat.exe`）

> ⚠️ 选的是**文件夹**，不是 `navicat.exe` 本身。

> 💡 **还没装 Navicat？** 点【自动安装 Navicat】，工具会自动下载并静默安装（几分钟），装完回到这一步。

---

### 第 3 步 · 选择激活方式，点「安装补丁」

先看「**激活方式**」那一行。点它可以在两种方式之间切换：

```
激活方式
┌────────────────────────┐
│  libcf.dll（默认）      │   ← 点按钮切换
└────────────────────────┘
```

| 方式 | 是否改 Navicat 文件 | 持久性 | 适合谁 |
|---|---|---|---|
| **`libcf.dll`**（默认） | **会**：改 `libcf.dll` + `navicat.exe` 里的公钥 | **持久**，重启 Navicat 后仍然生效 | ✅ **新手直接用这个** |
| **`version.dll`**（代理 DLL） | **不会**：只多一个代理 DLL，在进程内打补丁 | **持久**（DLL 常驻，每次启动 Navicat 自动加载） | 不想动 Navicat 文件、或官方更新频繁 |

选好后点【**安装补丁**】，日志区会显示进度。

**两种方式的日志不一样，看到哪条算成功：**

- 文件级（`libcf.dll`）：
  ```
  已关闭正在运行的 Navicat（1 个进程），等待文件解锁…
  补丁安装完成，校验通过。
  ```
- 代理 DLL（`version.dll`）：
  ```
  已释放代理 version.dll（49454 字节），常驻在安装目录；
  以后每次启动 Navicat 都会自动加载它完成补丁，不需要重复安装。
  ```
  （如果安装时 Navicat 正在运行，会先提示并关掉它——代理 DLL 只在启动时被加载。）

> ⚠️ **两种方式互斥**。文件级补丁会把函数入口改成跳板，此时代理 DLL **必然报**
> 「在 libcf.dll 的可执行节里没找到函数序言」——这不是 bug，是设计。
> **要切方式，先点【卸载补丁】，再装另一种。**

装好后会弹「补丁安装成功」提示框，点【确定】，工具会**接着自动往下走**。

---

### 第 4 步 · ★ 手动打开 Navicat，点「帮助 → 注册」〔最关键〕

#### 4.1 手动双击打开 Navicat

找到桌面上的 **Navicat Premium** 图标，**双击打开**。

> ⚠️⚠️ **必须是你自己双击打开的**。
> 工具**故意不自动启动** Navicat——实测由工具启动的 Navicat 权限/加载方式不同，激活会失败。
> 所以这一步工具会**一直等**你双击（最多等 4 分钟），检测到就自动继续。

打开时通常会弹「试用提醒」：

> ⚠️ **请点【关闭】或【取消】把这个提示框关掉。**
> **不要点里面的「购买」「立即激活」** —— 那是 Navicat 的在线激活通道，点了会联网失败、弹一串错误框，打乱后续流程。

#### 4.2 在 Navicat 里点「帮助 → 注册」

顶部菜单：`帮助(H) → 注册(R)`

会弹出「**注册**」窗口（左边是密钥框，右边有「激活」按钮）。

> 💡 左边那半是「永久许可证」，**不要在这里手输任何东西**——自动激活会替你填。

#### 4.3 回到工具，点【⚡ 开始激活】

**注册窗口显示出来之后**，切回工具点【⚡ 开始激活】。

> ⚠️ 如果注册窗口没开就点，工具会提示：
> 「没有检测到「注册」窗口。请先在 Navicat 里手动点一下：帮助 → 注册」

---

### 第 5 步 · 等待自动完成

点完就**双手离开键盘**，工具会自己跑完：

```
=== 第 1 步：定位 Navicat 安装目录 ===
=== 第 2 步：检查/安装补丁（激活前必须完成）===
=== 第 3 步：准备 Navicat（需要你手动双击打开）===
✔ 检测到 Navicat 已打开（pid=xxxx），自动继续。
=== 第 4 步：检查「注册」界面是否已打开 ===
注册窗口已打开
=== 第 5 步：检查是否已激活 ===
=== 第 6 步：开始激活 ===
已填入密钥，稍候…
…（自动按 Ctrl+Shift 点「激活」→ 进入手动激活窗口 → 读请求码 → 本机签发 → 填激活码 → 点激活）…
```

> 💡 过程中 Navicat 可能弹一个错误框（例如「激活次数上限」）——**正常流程的一部分**，工具会自己关掉它。不要手动干预。

耐心等 **10～30 秒**。会有一个「正在激活」的小窗口实时显示进度，**它只是提示，不影响操作**；
可以点【先去做别的】把它收起来（不会中断）。**不要反复点【开始激活】**。

---

### 第 6 步 · 确认结果

- **成功**：注册窗口的密钥框被填上、显示已激活；工具弹成功提示。
- **失败**：工具会打印失败原因，并提示改用【**手动激活**】（见第四节）。

> 💡 验证是否真的激活：关掉 Navicat 再重开，`帮助 → 注册` 里不应再提示试用。
> 文件级补丁（`libcf.dll`）和代理 DLL（`version.dll`）都是持久的；后者只要那个 DLL 还在安装目录，
> 每次启动 Navicat 都会自动加载。

## 三、两种激活方式怎么选

| | `libcf.dll`（文件级） | `version.dll`（代理 DLL） |
|---|---|---|
| 原理 | 给 `libcf.dll` 加 `.pmod` 节 + 改函数入口跳板，并替换 `navicat.exe` 里的请求码公钥 | 放一个代理 DLL，Navicat 启动时加载它，在进程内替换 PEM 并给函数装跳板 |
| 是否落盘 | 是（改 2 个文件，另存 `.orig` 备份） | 是（多一个 `version.dll`，不改 Navicat 原文件） |
| 持久性 | **持久**，重启/注销都有效 | **持久**，DLL 常驻，每次启动自动加载 |
| 官方更新后 | 被覆盖，需重新装补丁 | 不受影响 |
| 杀软观感 | 改文件，通常不报 | 代理 DLL 可能被部分安全软件误报（属误报） |
| 卸载 | 拷回 `.orig` | 删掉 `version.dll` |

**建议**：先用 `libcf.dll`；只有在「不想动 Navicat 文件」或「官方刚更新、不想每次重装」时才用代理方式。

> ⚠️ **切换方式必须先卸载**：文件级补丁占用了函数入口，代理 DLL 找不到原序言会直接失败。

## 四、手动激活（自动流程失败时的兜底）

自动激活依赖 GUI 自动化（找窗口、找控件），Delphi 自绘界面一变就可能失败。
所以工具里有一个**不依赖自动流程**的入口：主界面上的【**手动激活**】按钮。

### 4.1 操作步骤

```
① 在 Navicat 里点【帮助 → 注册】→ 复制「请求码」（一大段 base64，约 300+ 字）
② 切回工具 → 点【手动激活】→ 把请求码粘进去（或点【粘贴请求码】读剪贴板）
   → 确认「邮箱 / 公司」（会写进激活码的 N / O 字段，可留空）
③ 点【生成激活码】→ 点【复制激活码】
④ 把激活码粘回 Navicat 的注册窗口 → 点【激活】→ 完成
```

输入框会自动去掉换行与空格（请求码复制出来常带折行）。

### 4.2 注意事项

- **一个请求码只能签一次**；换 Navicat 版本、重装 Navicat、换机器后请求码都会变，要重新签。
- 激活码是**你自己私钥签的**，所以换掉 `keys/` 里的密钥对之后，之前所有激活码都作废。
- 手动激活与自动激活走的是**同一套签发实现**，效果一样。

## 五、常见问题

### ❓ 提示「没有检测到「注册」窗口」

先在 Navicat 里点一下 `帮助 → 注册`，让注册窗口真的显示出来，再点【开始激活】。
工具按「窗口类名 + 控件文本」定位，窗口没开就找不到。

### ❓ 自动激活一直失败，怎么办

1. 先用【**手动激活**】（第四节）——这条路径不走 GUI 自动化，最稳；
2. 如果手动激活也失败，看日志里的具体错误；
3. 确认补丁确实装好了（第三节的日志判据）。

### ❓ 提示「在 libcf.dll 的可执行节里没找到函数序言」

两种可能：
1. **你之前装过文件级补丁**（`.pmod` 已占入口）——先【卸载补丁】，再装代理 DLL 方式；
2. **Navicat 版本不匹配**——本项目按 18.0.x 的 21 字节序言匹配，换大版本需要重新适配。

### ❓ 目录里有个 `version.dll`，能删吗？

那是代理 DLL，**正在起作用的补丁本体**。删掉它，下一次启动 Navicat 就没有补丁了（激活会失效）。
要停用就走工具里的【卸载补丁】。

### ❓ 目录里有个 `~nvp_*.tmp`，是什么？

老版本留下的改名残留：早期代理加载后会尝试改名，Windows 不允许删除已映射的 DLL，只能改名。
现在不再改名了，如果有这个文件可以直接删（需管理员权限）。

### ❓ 激活成功了，但重启 Navicat 又变回未激活

先确认安装目录里 `version.dll` 还在不在：
- 在 → 可能是 Navicat 版本变了，或补丁被其它工具覆盖；
- 不在 → 补丁没装或被杀软删了，重新点一次【安装补丁】。

### ❓ 杀毒软件报毒 / 工具被杀掉

误报。处置：
1. 把 `Navicat18Tool-Offline.exe` 与 Navicat 安装目录（含 `version.dll`）加入杀软排除；
2. 临时关闭实时防护完成激活；
3. 如果报的是「可疑模块加载」，可以改用 `libcf.dll` 方式（改文件，不带代理 DLL）。

### ❓ 工具启动就闪退 / 没反应

1. 需要管理员权限：右键 →【以管理员身份运行】；
2. 确认 `.NET Framework 4.x` 存在（Win10/11 自带）；
3. 检查是不是被杀软静默删了。

### ❓ 官方更新 Navicat 之后补丁失效了

- `libcf.dll` 方式：官方会覆盖被改的文件，**需要重新装补丁**（并确认版本仍匹配 21 字节序言）；
- 代理 DLL 方式：不受更新影响，DLL 常驻即可一直生效。

### ❓ 卸载补丁后反而不能激活了

`libcf.dll` 卸载会拷回 `.orig`（原厂文件），此时请求码又重新用**厂商公钥**加密，
你的私钥解不开 → 自然激活不了。要么重新装补丁，要么用代理 DLL 方式。

## 六、卸载与还原

**工具内卸载**：主界面点【卸载补丁】。它会：

- `libcf.dll` 方式：把 `libcf.dll.orig` / `navicat.exe.orig` 拷回原位（即恢复原厂文件）；
- 代理 DLL 方式：删掉 `version.dll`（以及历史遗留的 `~nvp_*.tmp`）。

> ⚠️ **重要**：卸载会**删除 `.orig` 备份**。如果你之后还想再还原一次，就没有原厂文件了。
> 所以动手装补丁之前，建议自己额外复制一份 `navicat.exe` / `libcf.dll` 留底。
>
> 如果 `.orig` 已经丢了、又想彻底恢复原厂状态，只能**卸载重装 Navicat**。

## 七、安全与合规

### 7.1 私钥内嵌的风险

离线版 exe 里**编进了签发私钥**（OTP 密文形式）。这意味着：

- ✅ 好处：不需要服务器、不需要卡密、断网可用；
- ❌ 风险：**任何拿到你 exe 的人都能在本地为自己签发激活码**（OTP 只提高门槛，挡不住会逆向的人）。

**所以：自己构建的 exe 不要外发**；要给别人用，请让对方自己 clone 源码、生成自己的密钥对再构建。

## 附录 A · 目录里都有什么

| 文件 / 目录 | 作用 |
|---|---|
| `Navicat18Tool-Offline.exe` | 主程序（已内嵌代理 DLL 与签发私钥） |
| `keys/mykey_priv.pem` | **你的签发私钥**（构建时生成，`.gitignore` 已排除，别外传） |
| `keys/mykey_pub.pem` | 对应公钥（会被写进 `navicat.exe`） |
| `src/` | 全部源码（补丁器、代理 DLL、GUI） |
| `tools/gen_*.py` | 生成脚本（密钥 / payload / 离线签发代码 / 代理数据） |
| `build/*.cmd` | 构建脚本 |
| `docs/` | 原理与使用文档 |

**Navicat 安装目录里可能出现的东西**：

| 文件 | 谁生成的 | 能否删 |
|---|---|---|
| `libcf.dll.orig` / `navicat.exe.orig` | 装文件级补丁时自动备份 | **别删**（卸载靠它还原） |
| `version.dll` | 代理 DLL 方式的补丁本体（常驻） | 可删，但删了下次启动就没补丁 |
| `~nvp_xxxxxxxx.tmp` | `version.dll` 加载后被改名 | 可删（需管理员） |

## 附录 B · 补丁状态自检

不确定当前装没装、是哪种方式？按下面的判据看一眼就知道：

```
① 看 Navicat 目录
   ├─ 有 libcf.dll.orig + navicat.exe.orig   → 装过文件级补丁
   ├─ 有 version.dll                         → 装了代理 DLL 补丁
   └─ 都没有                                 → 没装补丁

② 看 libcf.dll 有没有 .pmod 节
   有  → 文件级补丁在位（入口已被改成 E9 跳板）
   没有 → 文件级补丁未装（此时代理 DLL 可以正常工作）

③ 看能否激活
   有 version.dll 且能激活 → 代理 DLL 生效中（每次启动自动加载）
```

> 工具日志里也会打印判据，例如
> `✔ 请求码公钥已经是我们的（无需替换）` / `✔ libcf 入口已经是跳板（补丁已在位）`
> / `在 libcf.dll 的可执行节里没找到函数序言`。
