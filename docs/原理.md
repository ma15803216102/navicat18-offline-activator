# 原理：Navicat 18 的离线激活是怎么被替换掉的

本文只讲机制，代码见 `src/`。

## 1. 许可模型：请求码 ↔ 激活码

Navicat 的「手动激活」是典型的**非对称密钥**流程：

```
客户端：  request = RSA_encrypt( pub_vendor, JSON{K, DI, ...} )        -> 请求码（base64, 256 字节密文）
厂商：    license = Sign( priv_vendor, JSON{K, N, M, O, T=1, DI, FA=1} ) -> 激活码（base64, 256 字节签名）
客户端：  Verify( modulus_vendor, license ) == true                     -> 写入本地许可
```

- 请求码的加密用 `navicat.exe` 里以**明文 PEM**（RSA-2048 SPKI，460 字节）存放的公钥；
- 激活码的验签**不用 OpenSSL**，由 `libcf.dll` 自带实现（`decrypt_RSA_NON_STD`），其模数**不以明文存在于任何文件**，只能在运行时由程序构造/使用。

因此要"自己签"，必须分别处理这两把钥匙。

## 2. 替换请求码公钥（改 `navicat.exe`）

RSA-2048 的 SPKI PEM 长度恒定（460 字节，CRLF，26+64×6+8+24 结构），所以可以**同长度原地覆盖**：

```csharp
int idx = FindPem(bytes);                       // 搜 "-----BEGIN PUBLIC KEY-----"
Array.Copy(ourPem, 0, bytes, idx, 460);         // 覆盖
File.WriteAllBytes(exe, bytes);
```

这样客户端会把"请求码"用**我们的公钥**加密，于是只有我们的私钥能解开。

## 3. 替换验签模数（改 `libcf.dll`）

模数不在文件里，只能运行时换。做法是**函数入口跳板**：

### 3.1 定位函数

`decrypt_RSA_NON_STD` 的入口 21 字节是稳定的 MSVC 序言：

```
4C 8B DC              mov  r11, rsp
53 56 57              push rbx / rsi / rdi
41 54 41 55 41 56 41 57   push r12 / r13 / r14 / r15
48 81 EC A0 01 00 00  sub  rsp, 1A0h
```

只扫**含 `IMAGE_SCN_MEM_EXECUTE` 的节**，按这 21 字节精确匹配即可定位（Navicat 18 中 RVA `0xEA850`，但代码不依赖这个常量）。

### 3.2 新增 `.pmod` 节

- 新节 VA = `align(最后一个节.VA + VirtualSize, SectionAlignment)`；
- 文件偏移 = `align(文件长度, FileAlignment)`；
- 节属性 `0x60000020`（代码 | 执行 | 读）；
- `NumberOfSections + 1`，`SizeOfImage` 同步放大。

节内容 = **352 字节跳板**：
- `+0x00 ~ +0x14`：原函数那 21 字节序言（跳板执行完要还原现场）；
- `+0x15 ~ +0x59`：把调用现场（`r9` 指向的对象）中的验签模数换成内嵌的 2048 位模数；
- `+0x5A`：`E9 rel32` 跳回 `入口 + 21`；
- `+0x60`：内嵌的 256 字节模数。

### 3.3 改写入口

```
入口+0:  E9 <rel32 到 .pmod>       ; 相对跳转，同模块内距离极小，永远在 ±2GB 内
入口+5:  90 × 16                  ; 填满被覆盖的 21 字节
```

执行顺序变成：

```
调用 decrypt_RSA_NON_STD
  -> E9 跳到 .pmod
     -> 换模数
     -> 执行原 21 字节序言（mov r11,rsp; push...; sub rsp,1A0h）
     -> jmp 回 入口+21
        -> 原函数余下逻辑（用我们的模数验我们的签名）
```

因为跳板与原函数在**同一个模块**内，`rel32` 不会溢出——这也是文件级补丁比"运行时 `VirtualAlloc` + `E9`"更稳的原因（后者必须把 shell 分配在目标函数 ±2GB 内，实测 `VirtualAlloc(NULL,...)` 可能给到相距上百 TB 的地址，直接 `c0000005`）。

## 4. 离线签发（不需要服务器）

`tools/gen_keys.py` 生成本机 RSA-2048 密钥对，并把公钥 PEM 写进 `src/pem_local.cs`；
`tools/gen_offline.py` 从私钥提取 `N`/`D`（`sig = EM^d mod n` 与 `m = c^d mod n` 只需要这两个），
以 **OTP 风格（每槽独立随机 pad + 纯异或）** 写成 `src/offline.cs`。

运行时 `OfflineSign.Make()`：

1. `m = request^d mod n` → 解出请求码内层 JSON（PKCS#1 v1.5 type-2 填充）；
2. 取 `K`/`DI`，拼许可 JSON：`{"K":...,"N":<email>,"M":"Navicat","O":<company>,"T":1,"DI":...,"FA":1}`；
3. PKCS#1 v1.5 **type-1** 填充：`00 01 FF..FF 00 <payload>`；
4. `sig = em^d mod n` → base64，即激活码。

> 三个常量必须严格一致：`M` 必须存在、`T` 恒为 `1`（不是时间戳）、字段顺序不能变。

## 4.5 另一种落地方式：运行时 `version.dll` 代理

不想改 Navicat 磁盘文件时，用代理 DLL 把上面两件事全部放到进程内存里做：

1. 把 `version.dll` 放进 Navicat 安装目录。它不在 KnownDLLs，而 `SafeDllSearchMode=1`
   下 exe 同目录优先，所以会被 `navicat.exe` 加载；
2. 代理把 3 个导出（`GetFileVersionInfoSizeW` / `GetFileVersionInfoW` / `VerQueryValueW`）
   转发给系统 `version.dll`，保证正常功能；
3. 后台线程里：
   - 扫主模块映像找 PEM 头，`VirtualProtect` 后原地替换成自己的公钥；
   - 轮询等 `libcf.dll` 加载，按同一 21 字节序言找函数，把入口改成 `E9` 跳到运行时 shell；
4. **运行时 shell 的 `E9 rel32` 只有 ±2GB**：必须把 shell 分配在目标函数附近
   （由近到远双向探测，上限 1.75GB），写入前校验 `rel/rel2` 都在 int32 内，
   超范围就放弃补丁——否则会 c0000005（实测 `VirtualAlloc(NULL,...)` 可能给出
   相距上百 TB 的地址）。

两种方式的 shell 是**同一份**字节（`pdata.cs` 的 `_shell`），所以换密钥后
`tools/gen_payload.py` 会一并更新它，文件级与运行时两条路都对得上。

### 4.6 为什么代理 DLL 加载后要“改名”而不是“删除”

代理 DLL 必须叫 `version.dll` 且位于 `navicat.exe` 同目录，加载器才会用它（它不在 KnownDLLs）。
但这样一个 DLL 常驻在安装目录，就是杀软每次扫描都能看到的静态样本。

实测（Windows 10/11，2026-10-19）两条关键事实：

| 操作 | 文件已被映射进进程时 |
|---|---|
| `DeleteFile(version.dll)` | **失败**（拒绝访问 —— 加载器持有映射） |
| `MoveFile(version.dll, ~nvp_xxx.tmp)` | **成功**（同卷改名） |
| 进程退出后删除改名后的文件 | 成功 |

所以工具的做法是：释放 `version.dll` → 用户启动 Navicat → 检测到该模块已加载（Toolhelp
枚举模块，比对完整路径）→ **改名**为随机 `~nvp_*.tmp` 并 `MoveFileEx(..., MOVEFILE_DELAY_UNTIL_REBOOT)`
登记重启删除。进程内的映射不受影响，而安装目录里不再有一个名为 `version.dll` 的文件。

代价：改名后原文件名消失，**下次启动 Navicat 需要重新释放一次**（工具里再点一次【安装补丁】）。

## 5. 版本适配

换 Navicat 版本时，唯一需要重做的是「21 字节函数序言」。若工具报
`版本不匹配：未在 libcf.dll 的可执行节中找到预期函数序言`，说明该版本的
`decrypt_RSA_NON_STD` 序言变了——用 IDA/x64dbg 找到新的入口字节，替换
`src/pdata.cs` 里的 `_pro` 即可（跳板本身不用改）。

## 6. 验证思路（不依赖人肉点界面）

- **公钥替换是否生效**：读回 `navicat.exe`，`FindPem` 后逐字节比对我们的 PEM；
- **`.pmod` 是否在位**：读节表找 `.pmod`；
- **签名是否被接受**：用公钥把激活码还原成 EM 块，断言 `head == 00 01`、连续 `0xFF ≥ 8`、随后 `00`，内层 JSON 与原文完全一致；
- **最终判据**：Navicat 注册界面由「未激活」变成「已激活」，且重启后仍保持。
